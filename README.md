# ADASS 2026 Proceedings — paper submissions

Every accepted contribution has a ready-made folder in `papers/<PID>/`, named after its
paper ID (for example `papers/C101/`). Find your PID in the [list of papers](#papers)
below. The PID
format is `XNNN`: `X` is the presentation type (I, C, P, F, B, T), the first digit is the
track number, and the last two digits number the papers within that track.

## For authors

The formatting rules are in [`docs/ManuscriptInstructions.pdf`](docs/ManuscriptInstructions.pdf)
(the ADASS guidelines) and [`docs/manual2010.pdf`](docs/manual2010.pdf) (the older ASP
manual; where they differ, the ADASS guidelines win). [`docs/ADASS_template.pdf`](docs/ADASS_template.pdf)
shows what the starting template looks like once built. [`docs/README_2026.md`](docs/README_2026.md)
is the README of the ADASS author template, updated for pull requests: the `make`
targets, index entries, checking, and what is in your folder.

1. Fork this repository, or create a branch if you have write access.
2. Edit **only** your own folder, `papers/<PID>/`:
   - `<PID>.tex`: your paper. It starts as the standard ADASS template, which also
     explains the formatting rules; replace its example content with your paper.
   - `<PID>.bib`: your references. It starts as the template's example references;
     replace them with your own.
   - figures: name them `<PID>_f1.eps`, `<PID>_f2.png`, and so on, and delete the
     template's `example.*` figures.
   - `makedefs`: check your surname and email.
3. Build and check it locally with a TeX Live installation:
   ```
   cd papers/<PID>
   make pdf      # builds <PID>.pdf
   make check    # runs the ADASS PaperCheck
   ```
4. Commit your `.tex`, `.bib`, figures and `makedefs`. Don't commit the PDF or other build
   output; `.gitignore` takes care of that.
5. Open a pull request titled `<PID>: <your paper title>`.

The CI builds your paper on every push to the PR, in its own `papers/<PID>/` directory,
using [latex-action](https://github.com/xu-cheng/latex-action) (latexmk with a full TeX
Live). A LaTeX error fails the check, and the error lines are shown in the job log.
PaperCheck problems show up as warnings for the editors to look at. You can download the
built PDF from the run's artifacts (one per paper), and the editors review the paper in
the PR.

If you'd rather use Overleaf, upload the contents of your `papers/<PID>/` folder as a new
project. It compiles there as it is. Copy your changes back into the folder for the PR.

## For editors

- `bash ci/build_papers.sh C101 P203` builds specific papers locally with `make`. With no
  arguments it builds every paper. GitHub Actions uses latex-action instead; it runs the
  same `pdflatex`/`bibtex` passes through latexmk.
- Running the *Build papers* workflow manually builds the whole set.
- This repo was generated by `make_author_templates.py` in the main
  ADASSProceedings2026 repo. When all PRs are merged, copy `papers/` back there:
  ```
  git clean -fdX papers/      # drop ignored build products first
  rsync -av papers/ ../ADASSProceedings2026/papers/
  ```
  Then continue with `pmake inc rsync` and `make asp1` / `make book0` as described in its `INGESTION.md`.
